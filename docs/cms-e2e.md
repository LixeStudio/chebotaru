# E2E-проверка сайта с настоящим CMS API (изолированно)

Как проверить связку Nuxt + Chebotaru CMS на **отдельной одноразовой базе**, не трогая рабочую БД CMS, её docker-том, production и Cloudflare. Используются только синтетические данные и адреса `@example.com`.

## 1. Одноразовая MySQL

Отдельный контейнер на другом порту, данные в памяти (`tmpfs`): после остановки ничего не остаётся. Имя базы оканчивается на `_test`, этого требуют тесты CMS.

```bash
docker run -d --rm --name chebotaru-e2e-db -p 127.0.0.1:3407:3306 --tmpfs /var/lib/mysql -e MYSQL_ROOT_PASSWORD=e2e_root -e MYSQL_DATABASE=chebotaru_e2e_test -e MYSQL_USER=chebotaru -e MYSQL_PASSWORD=e2e_only mysql:8.4
```

В Git Bash на Windows перед командой добавьте `MSYS_NO_PATHCONV=1`, иначе путь `/var/lib/mysql` будет искажён.

## 2. CMS на этой базе

В `Chebotaru-Admin` на нужной ветке:

```bash
cd apps/api
pnpm install
pnpm build
TEST_DATABASE_URL=mysql://chebotaru:e2e_only@127.0.0.1:3407/chebotaru_e2e_test pnpm test
```

Тесты накатывают миграции **только** на эту базу и проверяют API. Базы без `_test` в имени они не трогают.

Запуск API выполняйте **из папки без `.env`**, например из временной. Тогда `apps/api/.env` с адресом dev-базы не подхватится, а все настройки задаются переменными:

```bash
NODE_ENV=development PORT=3999 DATABASE_URL=mysql://chebotaru:e2e_only@127.0.0.1:3407/chebotaru_e2e_test CODE_HMAC_SECRET=<любые 32+ символа, только для теста> SETUP_SECRET=<тестовый ключ> MEDIA_STORAGE_DIR=<временная папка> TRUST_PROXY=1 node <путь>/apps/api/dist/main.js
```

- `TRUST_PROXY=1` — Nuxt выступает одним прокси перед CMS.
- Админку запустите с `VITE`-адресом этого API, письма смотрите в Mailpit (`pnpm services:up` поднимает только Mailpit и MySQL dev; dev-MySQL для этой проверки не нужен).

## 3. Тестовые данные (через админку)

1. Первый вход: `/setup` с `SETUP_SECRET`, код — из Mailpit.
2. «Языки»: подключите `en-US`, `ru-RU`, `uk-UA`. Без этого Public API отвечает `404 locale_not_available`, а сайт показывает «временно недоступно» с 503.
3. Медиа: загрузите несколько своих тестовых изображений.
4. Каталог: 3–5 картин с полным переводом на en и ru и одна картина **без** uk. Одну картину сделайте в EUR. Опубликуйте.
5. Блог: 2–3 статьи (заголовки H2–H4, текст с жирным, курсивом, ссылкой и списками, галерея из 5–7 фото). Одна статья без uk. Опубликуйте.

## 4. Сайт

```bash
NUXT_CMS_API_BASE=http://127.0.0.1:3999 NUXT_PUBLIC_CMS_MEDIA_BASE=http://127.0.0.1:3999 npm run build
PORT=4310 NUXT_CMS_API_BASE=http://127.0.0.1:3999 NUXT_PUBLIC_CMS_MEDIA_BASE=http://127.0.0.1:3999 node .output/server/index.mjs
```

Юнит-тесты сайта: `npm test`.

## 5. Что проверить

- [ ] Главная (6 работ, 2 статьи), каталог, блог, картина и статья на en/ru/uk; картинки грузятся с `:3999/api/public/v1/media/...`.
- [ ] Цена в EUR показывается со знаком `€`.
- [ ] Статья: форматирование, ссылки, списки, галерея рядами по ≤4.
- [ ] Картина/статья без uk: `/uk/...` даёт 302 на доступный язык. Переключатель языка в меню не даёт ошибок в консоли. В `<head>` нет `hreflang="uk"`.
- [ ] Несуществующий id — 404, старый slug — 301.
- [ ] Снятие с публикации или правка: в списках изменения видны не позже чем через 15 с, на странице записи — не позже чем через 30 с (кэш сервера Nuxt).
- [ ] Остановите API: в пределах TTL сайт ещё отдаёт данные, после — каталог и блог отвечают 503 с текстом «временно недоступны», детали — 503. Запустите API: сразу 200.
- [ ] Подписка в форме (футер или «Контакты»):
  - новый адрес → «Thank you!…»;
  - тот же адрес ещё раз → то же сообщение, дубликата в «Подписчиках» нет;
  - неверный адрес → «Please enter a valid email address.»;
  - больше 10 попыток в минуту → «Something went wrong…» (лимит CMS).
- [ ] В админке «Подписчики» новый адрес виден с обеими рассылками; его можно изменить и удалить.
- [ ] В логах Nuxt и CMS нет адресов email.
- [ ] `/sitemap_index.xml`: записи без перевода отсутствуют в sitemap этого языка.

## 6. Уборка

```bash
docker rm -f chebotaru-e2e-db
```

Удалите временную папку `MEDIA_STORAGE_DIR`. В рабочих базах ничего не создаётся.
